Authentication

Sign-in posture, session enforcement, MFA, and SSO.

Live now

  • Server-side session revoke ENFORCED — JWTs and cookies stop working immediately on logout / revoke-all-tokens. Pre-v0.4.10 this was shadow-mode (write-only); now the middleware consults sessions.revoked_at on every authenticated request. Legacy sessions without a sid / jti claim still authenticate (graceful fallback).
  • Password reset — forgot-password + reset-password live at /app/forgot-password. 1-hour token TTL, single-use, bumps tokens_valid_after on consume so every other session for that user is invalidated. Honest about SMTP failures (BUG-045 v0.4.15). Shipped v0.4.1.
  • Bootstrap admin password persistence — v0.4.16: a password reset is no longer overwritten by the env var on the next container restart. Recovery flag REBOOTER_BOOTSTRAP_ADMIN_FORCE_PASSWORD_ON_STARTUP=1 restores the legacy "always reconcile" behaviour for "I forgot my password" recovery.
  • Login rate limit — 30/min, 200/hr per IP, with a documented exemption mechanism for the QA host (v0.1.4 + v0.4.4).
  • Invitations — invite-via-email with 30-day TTL (v0.4.1). Token-based; signed with the hub's HMAC key.

Queued

  • Site-as-scope RBAC — per-site role assignments. Awaiting your redline on RFC-003 §RBAC questions (#1–#4: site-as-scope contract, migration plan, audit retention, invite shape). Until those land, every admin remains org-wide.
  • TOTP MFA enrolment — gated on RBAC migration above.
  • Google + GitHub OIDC sign-in — gated on RBAC migration above.
  • Session idle timeout (editable here) — currently env-var (REBOOTER_SESSION_IDLE_TIMEOUT_SECONDS); editable UI lands with the broader runtime-settings work.

See docs/redesign-continuation-plan.md for the full map of what shipped vs what's queued.
